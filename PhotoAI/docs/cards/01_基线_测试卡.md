# 01-T 基线 · 冻结断言

> 这些断言是**验收标准**：实现方不许改断言、不许删断言、不许把 `assertThat` 换成打印。
> 跑法：`mvn8 -B -ntp test`（`mvn8` 在 `windows-java-maven-jdk8` 技能 `scripts/` 里）。
> 测试库：`db_pg_test`（由 `bash db/migration/run_verify.sh db_pg_test` 生成，**禁止连 `db_pg`**）。

## 0. 测试基座（必须先有）

- `BaseIntegrationTest`：`@SpringBootTest(webEnvironment=MOCK)` + `@AutoConfigureMockMvc` + `@ActiveProfiles("test")`
- `application-test.yml`：连 `db_pg_test`；JWT 用固定测试密钥
- 发 token 的工具方法：用 `JwtUtils` 直接签（`uid` + `role`），三种身份：
  - `TOKEN_普通`：`uid=U-normal`，`role=普通用户`
  - `TOKEN_管理员`：`uid=U-admin`，`role=管理员`
  - `TOKEN_无角色`：`uid=U-ghost`，`role=`（空）
- 每组测试**结束回滚**（`@Transactional`）或自己清理写入的数据

## 1. AuthzTest（鉴权 401 / 403 / 200）

| # | 场景 | 请求 | 期望 |
|:-:|---|---|---|
| T1.1 | 无 token 访问管理接口 | `GET /user/list` 无 `Authorization` | **401**，`code=unauthorized`，`data=null` |
| T1.2 | 坏 token | `Authorization: Bearer xxx.yyy.zzz` | **401**，`code=unauthorized` |
| T1.3 | 普通用户访问管理接口 | `GET /user/list` + `TOKEN_普通` | **403**，`code=forbidden`（**不是** 302、**不是** 500） |
| T1.4 | 管理员访问管理接口 | `GET /user/list` + `TOKEN_管理员` | **200**，`code=ok` |
| T1.5 | token 无角色字段 | `GET /user/list` + `TOKEN_无角色` | **403**（按最小权限，不许当普通用户放行） |
| T1.6 | 普通用户访问自己的资料 | `GET /user/{uid}` 自己 + `TOKEN_普通` | **200**（不能误伤） |

> 注：`/user/list` 返回分页结构即可，本卡不管它的数据结构，只看状态码与 `code`。

## 2. ProfileWhitelistTest（提权必须被静默拦掉）

**前置**：测试库存在一条 `uid=U-normal`、`role=普通用户`、`vote=0`、`status=正常` 的用户（测试里自行插入并在结束时删除）。

| # | 场景 | 请求体（PUT `/user/update`） | 期望 |
|:-:|---|---|---|
| T2.1 | 普通用户自提权 | `{"uid":"U-normal","role":"管理员"}` | **200 或 200 语义**，但库里 `role` **仍是 `普通用户`** |
| T2.2 | 普通用户改积分 | `{"uid":"U-normal","vote":"9999"}` | 库里 `vote` **仍是 `0`** |
| T2.3 | 普通用户改状态 | `{"uid":"U-normal","status":"禁用"}` | 库里 `status` **仍是 `正常`** |
| T2.4 | 普通用户改密码（本卡不做改密） | `{"uid":"U-normal","pwd":"newpass"}` | 库里 `pwd` **未变**（后续卡三再开） |
| T2.5 | 普通用户改他人资料 | `{"uid":"U-other","uname":"x"}` | **403** |
| T2.6 | 普通用户改自己的合法字段 | `{"uid":"U-normal","uname":"新名字","avatar":"/a.png"}` | **200**，库里 `uname`/`avatar` 已更新 |
| T2.7 | 管理员改角色 | `{"uid":"U-normal","role":"管理员"}` + `TOKEN_管理员` | **200**，库里 `role=管理员`（管理员路径不许被白名单误伤） |

> T2.1–T2.3 **必须是"静默忽略"**：返回成功但不落库。若实现选择返回 400，**本卡不通过**（架构 §7 定的是忽略）。

## 3. ErrorEnvelopeTest（统一响应 + HTTP 语义）

| # | 场景 | 请求 | 期望 |
|:-:|---|---|---|
| T3.1 | 路径不存在 | `GET /no/such/path` | **404**，body 有 `code=not_found`、`msg`、`data=null` |
| T3.2 | 方法不允许 | `DELETE /user/list` | **405**，`code=method_not_allowed`（或映射到 `invalid_request`，二者取一并在卡面固定） |
| T3.3 | 缺必填参数 | `POST /user/login` 空 body | **400**，`code=invalid_request` |
| T3.4 | 参数类型错误 | `GET /user/{uid}` 传 `uid` 超长/非法字符 | **400**，`code=invalid_request` |
| T3.5 | 内部异常 | 注入一个必然抛 `RuntimeException` 的路径（测试用 `@MockBean` 让某 service 抛异常） | **500**，`code=internal_error`，**body 不含** `Exception`、`java.`、`SQL`、堆栈 |
| T3.6 | 响应信封一致 | 任意上述响应 | 顶层只允许 `code/msg/data` 三个键（多一个 `trace` 之类算不通过） |
| T3.7 | 不泄露敏感 | 任意错误响应全文 | 不含 `138` 开头手机号、不含 `Bearer `、不含 `openid` |

## 7. R05 追加断言（Q01 对抗测试产出，2026-10-21）

**19 条，见 `docs/cards/01_基线_返工_R05.md` §2**（T7.1–T14.1）。原 28 条必须继续全绿，合计 **≥47**。

要点复述（防漏）：
- 路径变体 `%6cist` / `list;x=1` / `//list` / `li%73t` / `%61dd` / `%64isable` → 普通用户 **403**，管理员 **正常 200**
- 任何响应体**不得含 `"pwd"`**；非管理员看手机号脱敏 `138****0005`
- 空/未知角色 → 读他人 **403**
- token 主体不存在 / `status!=正常` → **401**
- 登录失败 **HTTP 401**
- 成功响应顶层只有 `code/msg/data`（**无 `total`**，分页进 `data.list/data.total`）
- 非法 `role/status` → **400**（不是 500）
- 不存在资源 → **404**
- `/page/admin/**` 普通用户 → **302 到 `/login/page`**
