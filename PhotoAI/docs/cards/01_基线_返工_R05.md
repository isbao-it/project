# 01-R05 安全加固（V-01 ~ V-09）

## 0. 必须修掉的实测漏洞

| 编号 | 严重度 | 现象（已复现） | 修法 |
|:-:|:-:|---|---|
| V-01 | **严重** | `GET /user/%6cist`、`/user/list;x=1`、`/user//list`、`/user/li%73t` 用**普通用户** token 返回 200 + 10 条用户 | ① 拦截器改用 `UrlPathHelper.getPathWithinApplication(request)` 取**解码+去矩阵参数**后的路径去匹配；② **双保险**：`userController` 的管理方法（list/add/update 的管理员分支/disable/enable/batch）加 `@RequiresRole("管理员")` 注解，拦截器在 `preHandle` 读 `HandlerMethod` 上的注解判断，**不依赖 URI 字符串** |
| V-02 | **高** | `/user/list` 每条记录带 `pwd`（60 位 bcrypt）+ 手机号明文 | `User.pwd` 加 `@JsonProperty(access = WRITE_ONLY)`（可入参、永不输出）；`/user/list` 手机号按角色脱敏：管理员看全、其他人看 `138****0005` |
| V-03 | 中 | 空角色 token `GET /user/{uid}` → 200 可读任意人 | 角色判定改**白名单**：只有 `管理员` 全通、`普通用户` 限本人；**未知/空角色一律 403**（不是当普通用户） |
| V-04 | 中 | token 主体 `U-admin` 在库里不存在仍 200 | 验签后查 `user`：不存在或 `status != 正常` → **401 unauthorized**；每请求查一次即可，别加缓存直到卡 09 |
| V-06 | 中 | 控制器手工错误 `HTTP 200 + 数字 code + total`（登录失败、`/user/info` 404、`/view/...` 404、`/user/add` 400） | 手工错误分支改抛业务异常（`BizException(code,httpStatus)`），由 `GlobalExceptionHandler` 统一出 `{code,msg,data}` + 正确 HTTP；**成功响应不得带 `total`**（分页结构统一为 `data:{list,total}`） |
| V-07 | 低 | 不存在的作品 `code=ok,data=null` | 404 `not_found` |
| V-08 | 低 | `role=ADMIN`、`status=HACKED`、`role=" 普通用户"` → **500** | 入口对 `role/status` 做枚举白名单校验 → 400 `invalid_request`；值统一 `trim` 后再校验，非法即拒 |
| V-09 | 低 | 普通用户可加载 `/page/admin/index` | 页面路径同样按角色拦；`/page/admin/**` 非管理员 → 302 到登录页（页面请求用重定向，接口用 403） |

## 1. 不许做的事

- 不许把 `AuthInterceptor` 的 URI 前缀表**只**加几个 `%6c` 特例（必须走规范化/注解）
- 不许用 `@JsonIgnore` 代替 `WRITE_ONLY`（会让 `PUT /user/update` 收不到 `pwd`，改密功能以后做不了）
- 不许把 V-04 的库查询放到 `preHandle` 里每个静态资源都查（只对 `/user/** /pwork/** /view/** /upload/** /admin/**` 查）
- 不许削弱/删除已有 28 条断言；不许 `@Disabled`
