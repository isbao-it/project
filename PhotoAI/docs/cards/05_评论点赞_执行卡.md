## 实现约束与并行交接

- GET /comment/list匿名可读；仅展示作品，body无。POST从身份取作者，content按Unicode 1–500且非空白，保留原文；先MsgSecCheck再插入。

- DELETE评论只允许作者/管理员，基于完整复合主键删除，不误删其它pid/uid同cid记录；不存在返回404。

- 非展示或不存在作品的评论读取/添加/删除、点赞/取消均404，作者/管理员也不能绕过；身份缺失先401。ID为string，合法不存在404、格式错误400。

- 点赞对象为targetid=pid,targettype='帖子'、时间likect；唯一键(uid,targetid,targettype)。重复POST/DELETE都200 ok；仅真正插入/删除时同一事务原子变更likep一次，取消计数不小于0。

- 并发重复在本Service内处理唯一键竞争，不能给全局异常处理增加DuplicateKeyException→409；故障回滚须同时撤销记录与计数。count只算该作品帖子点赞，不混评论点赞或其它作品。

- Comment返回cid/pid/uid/content/createdAt/author(uid,nickname,avatar)，不返回likecom；时间按Asia/Shanghai带秒偏移；count/total用Long承接，JSON非负整数。组件只用字符串ok判断成功，401转登录。

冻结§3.4内部契约：
消费03唯一 `MsgSecCheck.check(String uid, String content): void`：通过正常返回、拒绝CONTENT_REJECTED/422、不可用SERVICE_UNAVAILABLE/503；评论检查失败不落库，不自建放行Bean。03还提供 `WorkQueryService.detail(String pid): Map<String,Object>`、`list(String tab,String category,int page,int size): Map<String,Object>`、`mine(String uid,String status,int page,int size): Map<String,Object>`，返回冻结详情、Page<Work>、Page<MineWork>。detail有浏览+1副作用，不能为点赞/评论存在性校验随意调用；本卡Mapper只读验证展示作品。02提供WeChatClient.code2Session(String code): String（只返openid）与ProfileService.info/publicProfile/updateProfile冻结Map，本卡取已验证uid，不读写User新增字段。05只用LikeMapper维护likep，不改03的PworkService；06/07组件和详情标记各自独占，不修改03详情js/wxss。并行Mock严格按§3.4签名，集成改用唯一已合入接口。
