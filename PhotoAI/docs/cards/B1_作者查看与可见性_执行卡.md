# B1 作者查看与可见性管理执行卡

## 1. 目标

两项后端能力，服务于「我的作品」管理：

1. **作者能查看自己的非展示作品**（待审核 / 隐藏 / 已驳回），用于点开详情与进入编辑页；
2. **作者能在「展示」与「隐藏」之间切换自己作品的可见性**（下架 / 重新上架）。

其他人的行为**完全不变**。

现状：`GET /pwork/{pid}` 的 SQL 写死 `wstatus='展示'`，作者看自己的非展示作品一律 404；且没有任何作者可用的状态切换接口。

依据：`docs/接口冻结_v1.md` §1.3 #6、#9、#10（本次为**受控扩展**，见 §6）。

## 3. 能力一：作者可查看自己的非展示作品

### 3.1 Controller

`PworkController.getById` 增加 `HttpServletRequest request` 参数，新增私有方法解析**可选**身份：

```java
/**
 * 读取可选身份：无令牌、令牌无效或过期一律返回 null，不影响匿名访问。
 * @param request 原始请求
 * @return 已验证的 uid，匿名时为 null
 */
private String optionalUid(HttpServletRequest request) {
    String authHeader = request.getHeader("Authorization");
    if (authHeader == null || !authHeader.startsWith("Bearer ")) {
        return null;
    }
    try {
        return jwtUtils.getUidFromToken(authHeader.substring(7));
    } catch (RuntimeException ex) {
        return null;
    }
}
```

`jwtUtils` 通过构造器注入。调用改为 `workQueryService.detail(pid, optionalUid(request))`。

### 3.2 Service / Mapper

- `WorkQueryService.detail(String pid, String viewerUid)`
- `WorkQueryMapper.incrementView(@Param("pid") String pid, @Param("viewerUid") String viewerUid)`
- `WorkQueryMapper.displayed(@Param("pid") String pid, @Param("viewerUid") String viewerUid)`

XML 两条 SQL 的 WHERE 改为：

```sql
WHERE p.pid=#{pid} AND (p.wstatus='展示' OR p.uid=#{viewerUid})
```

`incrementView`：

```sql
UPDATE pwork SET viewcount=COALESCE(viewcount,0)+1
WHERE pid=#{pid} AND (wstatus='展示' OR uid=#{viewerUid})
```

**关键**：`viewerUid` 为 `null` 时 `p.uid = NULL` 恒为 UNKNOWN，匿名与普通用户自动退化为「只有展示作品」，无需额外分支。不要写多余的条件。

## 4. 能力二：作者切换展示 / 隐藏

### 4.1 接口契约

```
PUT /pwork/{pid}/status
权限：登录、仅作者本人
Body: { "status": "展示" | "隐藏" }
响应 data: { "pid": "...", "status": "展示" | "隐藏" }
错误：400 invalid_request（status 不是这两个值之一）
      404 not_found（作品不存在，或不是本人作品）
      409 conflict（作品当前状态为 待审核 / 已驳回，不允许直接切换）
      401 unauthorized（未登录，由现有拦截器处理）
```

规则：

- 只允许 **展示 ↔ 隐藏** 互相切换；
- **待审核 / 已驳回** 状态的作品不能由作者直接改成展示（必须走审核），返回 409；
- 改成当前相同状态视为幂等成功（返回 200，不报错）。

### 4.2 实现

`PworkController` 新增：

```java
@PutMapping("/{pid}/status")
public AjaxResult updateStatus(@RequestAttribute String uid, @PathVariable String pid,
                               @RequestBody Map<String, Object> body) {
    return AjaxResult.success(pworkService.updateVisibility(uid, pid, body));
}
```

`PworkService.updateVisibility(String uid, String pid, Map<String,Object> body)`：

1. 取 `body.get("status")`，必须是字符串且等于 `展示` 或 `隐藏`，否则 `INVALID_REQUEST`；
2. 调 Mapper 做条件更新；
3. 更新 0 行时，再查一次判断：
   - 作品不存在或 `pwork.uid != uid` → `NOT_FOUND`
   - 当前状态为 `待审核`/`已驳回` → `CONFLICT`
   - 若当前状态已等于目标状态 → 视为幂等成功（返回 200）
4. 返回 `{pid, status}`。

`PworkMapper` 新增：

```java
int updateVisibility(@Param("pid") String pid, @Param("uid") String uid, @Param("status") String status);
```

`PworkMapper.xml`：

```sql
<update id="updateVisibility">
    UPDATE pwork SET wstatus=#{status}
    WHERE pid=#{pid} AND uid=#{uid} AND wstatus IN ('展示','隐藏')
</update>
```

再新增一个只读查询用于判定错误类型（不要用 `SELECT *`，只取必要列）：

```java
Map<String, Object> findOwnerStatus(@Param("pid") String pid);
```

```sql
<select id="findOwnerStatus" resultType="java.util.LinkedHashMap">
    SELECT uid, wstatus FROM pwork WHERE pid=#{pid}
</select>
```

## 6. 验收（必须真跑，贴 HTTP 状态码与响应片段）

**能力一**
1. 匿名 `GET /pwork/<展示pid>` → 200
2. 匿名 `GET /pwork/my12`（待审核）→ **404**
3. 作者本人 token `GET /pwork/my12` → **200**，`data.work.wstatus` = 待审核
4. 他人 token 请求同一 pid → **404**
5. `Authorization: Bearer garbage` 请求展示作品 → **200**（无效令牌不得变成 401/500）

**能力二**
6. 作者把 `my11`（展示）改成 `隐藏` → 200，`data.status` = 隐藏；再查列表确认它不在公开列表里
7. 同一接口再改成 `展示` → 200，恢复
8. 作者把 `my12`（待审核）改成 `展示` → **409 conflict**
9. 他人 token 改 `my11` 状态 → **404**
10. 匿名调用该接口 → **401**
11. `status: "已驳回"` → **400 invalid_request**
12. 重复提交相同状态（展示→展示）→ **200**（幂等）

**回归**
13. `GET /pwork/list`、`GET /pwork/mine`、`GET /pwork/similar/{pid}` 各打一次，状态码与改造前一致
14. 编译：`mvn -q compile`（或项目等价命令）退出码 0

未执行项必须标注「未验证」，禁止写「已测试通过」。

## 8. 硬约束

- **不得放宽匿名可见性**：非作者、无令牌看非展示作品必须仍 404。
- **不得把 `/pwork/{pid}` 加入登录强制拦截列表**（它必须保持匿名可访问展示作品）；
  `/pwork/{pid}/status` 则必须是登录接口。
- **不得允许作者把 待审核/已驳回 直接改成展示**（绕过审核），必须 409。
- 不得改审核流程（`/admin/work/*`）、不得新增其它接口。
- 不得动 `PworkController` 里 `mine` / 发布 / 更新 / 删除 的既有行为。
- 不做任何 git 操作。
- 写盘只能 Python / `apply_patch`；禁止 PowerShell 重定向写 Java/XML（会破坏中文注释）。
