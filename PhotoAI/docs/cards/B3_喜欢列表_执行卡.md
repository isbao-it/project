# B3/F12 喜欢列表执行卡

## 1. 目标

把「我的」页里目前显示「喜欢列表暂未开放」的**喜欢** tab 接上真实数据：

- 后端新增 `GET /like/mine`：返回当前用户点赞过的**展示作品**分页列表；
- 前端「喜欢」tab 改为真实列表，结构与「收藏」tab 一致。

收藏 tab 已经可用（`/favorite/mine`），本轮**不动它**。

依据：`docs/接口冻结_v1.md` §1.5 #23/#24（点赞）、§1.6 #28（收藏列表的既有范式）。

## 2. 接口设计

```
GET /like/mine?page=1&size=10
权限：登录
响应 data: { list: Work[], total: number }
排序：点赞时间 likect 降序，lid 升序兜底
过滤：只含 wstatus='展示' 的作品；targettype='帖子'
```

错误：`401 unauthorized`（未登录）、`400 invalid_request`（page/size 越界，与其它列表一致：page≥1、size 1–50）。

## 3. 后端实现

### 3.1 Controller（`controller/LiketableController.java`）

新增：

```java
/**
 * 查询我点赞过的展示作品。
 * @param uid 已验证身份
 * @param page 页码
 * @param size 页长
 * @return list/total 分页信封
 */
@GetMapping("/mine")
public AjaxResult mine(@RequestAttribute String uid,
                       @RequestParam(defaultValue = "1") int page,
                       @RequestParam(defaultValue = "10") int size) {
    return AjaxResult.success(likeService.mine(uid, page, size));
}
```

注意：该路由必须落在登录拦截范围内（`/like/**` 现有规则已覆盖，不要改拦截器）。

### 3.2 Service（`service/LikeService.java` + `impl/LikeServiceImpl.java`）

```java
Map<String, Object> mine(String uid, int page, int size);
```

实现：

- 校验 `page >= 1`、`1 <= size <= 50`，否则 `INVALID_REQUEST`；
- `offset = (page - 1) * size`；
- `total = likeMapper.countByUser(uid)`；`rows = likeMapper.pageByUser(uid, size, offset)`；
- 返回 `{list: rows, total}`（**字段名必须是 `list` 与 `total`**，与 `/pwork/list` 一致）。

### 3.3 Mapper（`mapper/LikeMapper.java` + `resources/mapper/LikeMapper.xml`）

```java
List<Map<String, Object>> pageByUser(@Param("uid") String uid,
                                     @Param("size") int size,
                                     @Param("offset") long offset);

Long countByUser(@Param("uid") String uid);
```

XML（**复用作品列表的列定义与 resultMap，保证返回结构与 `/pwork/list` 完全一致**）：

```xml
<select id="pageByUser" resultMap="com.pg.mapper.WorkQueryMapper.Work">
    SELECT <include refid="com.pg.mapper.WorkQueryMapper.Columns"/>
    FROM liketable l
    JOIN pwork p ON p.pid = l.targetid AND p.wstatus = '展示'
    LEFT JOIN user u ON u.uid = p.uid
    LEFT JOIN pclist c ON c.pcid = p.pcid
    WHERE l.uid = #{uid} AND l.targettype = '帖子'
    ORDER BY l.likect DESC, l.lid ASC
    LIMIT #{size} OFFSET #{offset}
</select>

<select id="countByUser" resultType="java.lang.Long">
    SELECT COUNT(*)
    FROM liketable l
    JOIN pwork p ON p.pid = l.targetid AND p.wstatus = '展示'
    WHERE l.uid = #{uid} AND l.targettype = '帖子'
</select>
```

## 4. 前端实现（`pages/mine/mine.wxml` + `.js`）

- 「喜欢」tab 从固定空态改为真实列表：
  - 与「收藏」tab 同构：独立分页状态（`likes / likesPage / likesTotal / likesNoMore / likesLoading / likesError`）；
  - 首次切到该 tab 才请求 `GET /like/mine`，不在 `onShow` 预加载；
  - 触底加载下一页（与收藏同一套 `onReachBottom` 分发逻辑，加 `tab === 'likes'` 分支）；
  - 空态文案：「还没有喜欢的作品」；
  - 卡片视觉与收藏卡片完全一致（图 + 标题 + 作者），**不要显示审核状态标签**（点赞的都是展示作品）。
- 三个列表（作品 / 收藏 / 喜欢）的请求必须**互不干扰**：各自独立的 `_requestId` 或独立的分页状态，切换 tab 不重置对方数据。
