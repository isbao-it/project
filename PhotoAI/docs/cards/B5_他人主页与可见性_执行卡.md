# B5 他人主页与可见性设置执行卡

## 1. 目标

支撑「点别人头像 → 看他的主页」，并让主页拥有者能控制哪些内容对外可见：

1. **他人作品列表**：`GET /user/{uid}/works` —— 只返回该用户的「展示」作品；
2. **他人收藏列表**：`GET /user/{uid}/favorites` —— 受 `user.vis_favorite` 控制；
3. **他人喜欢列表**：`GET /user/{uid}/likes` —— 受 `user.vis_like` 控制；
4. **主页聚合信息**：扩展 `GET /user/{uid}`，补统计与可见性结果；
5. **可见性设置**：`PUT /user/privacy` —— 本人修改自己的两个开关。

**作品列表不需要开关**：主页作品 tab 天然只显示「展示」作品，隐藏/待审核/已驳回一律不出现。

## 4. 接口定义

### 4.1 `GET /user/{uid}/works`

```
权限：匿名
Q: page(默认1,≥1)、size(默认10,1–50)
响应: { list: Work[], total: N }
筛选: p.uid = #{uid} AND p.wstatus = '展示'
排序: p.cwtime DESC, p.pid ASC
错误: 400 invalid_request；404 not_found（用户不存在）
```

### 4.2 `GET /user/{uid}/favorites`

```
权限：匿名
筛选: favorite.uid = #{uid} AND p.wstatus = '展示' AND 目标用户 vis_favorite = 1
排序: favorite.ct DESC, favorite.fid ASC
响应: { list: Work[], total: N }
可见性: 目标用户 vis_favorite = 0 且 请求者 uid ≠ 目标 uid → 403 forbidden（"该用户的收藏不可见"）
        目标用户不存在 → 404
```

### 4.3 `GET /user/{uid}/likes`

同 4.2，换成 `liketable`（`targettype='帖子'`）、`vis_like`、排序 `liketable.likect DESC, liketable.lid ASC`。

### 4.4 扩展 `GET /user/{uid}`

在现有响应基础上**纯增量**追加：

```json
{
  "uid": "...", "uname": "...", "avatar": "...", "bio": "...",
  "worksCount": 12,          // 该用户「展示」作品数
  "followingCount": 8,       // 他关注了多少人
  "followersCount": 15,      // 多少人关注他
  "followed": false,         // 当前请求者是否已关注他（匿名 false）
  "showFavorites": true,     // 收藏 tab 是否应显示（本人恒 true）
  "showLikes": true          // 喜欢 tab 是否应显示（本人恒 true）
}
```

规则：
- `showFavorites` = `vis_favorite=1 || 请求者uid==目标uid`
- `followed` = 存在 `follow.uid=请求者 AND follow.tuid=目标`，匿名为 `false`
- 保留原有字段与格式，不得删除或改名
- **不得输出 pwd / openid**（沿用现有 R05 脱敏规则）

### 4.5 `PUT /user/privacy`

```
权限：登录（@RequestAttribute String uid）
B: { "visFavorite": true|false, "visLike": true|false }   两个字段都必须存在且为布尔
响应: { visFavorite: bool, visLike: bool }
错误: 400 invalid_request（缺字段/类型非布尔）；401 unauthorized
说明: 只改当前登录用户自己的记录，不接受 body 里传 uid
```

## 6. 实现要点

1. **必须复用 `Work` 字段投影**（`FIELDS` 白名单），三个新列表的返回字段与 `/pwork/list` 完全一致。
2. 三个列表都要 `total`，且 `total` 与列表使用**同一 WHERE 条件**（含可见性判断）。
3. 排序必须带主键兜底，保证分页稳定。
4. 不存在用户返回 404，不要返回空列表冒充。
5. 可见性 403 只在「目标用户关闭 + 请求者不是本人」时触发；本人看自己永远 200。
6. `followed` 判断用现有 `follow` 表（`uid`=关注者、`tuid`=被关注者）。
7. 统计口径：`worksCount` 只数 `wstatus='展示'`。
