# B6 移除粉丝接口执行卡

## 1. 目标

新增 `DELETE /follow/follower/{uid}`：让用户把「已经关注我的人」从我的粉丝列表里移除，对应删除 `follow` 表中 `uid=对方 AND tuid=我` 的那一行。

## 2. 现状（已核实）

`FollowController` 现有：

```
POST   /follow/{uid}          关注
DELETE /follow/{uid}          取关（我取消关注对方）
GET    /follow/following      我关注的人
GET    /follow/followers      我的粉丝
```

`follow` 表：`fid`(PK)、`uid`(关注者)、`tuid`(被关注者)、`ct`。

**没有移除粉丝的接口**。路由不冲突：`DELETE /follow/{uid}` 是单段，新接口是三段（`/follow/follower/{uid}`），Spring 不会混淆。

## 3. 接口定义

```
DELETE /follow/follower/{uid}

权限：登录（@RequestAttribute String uid = 当前用户）
P: uid 是被移除的粉丝（对方的 uid），格式 [A-Za-z0-9_-]{1,64}
响应: { removed: boolean, followersCount: N }
      followersCount = 移除后我的粉丝总数
错误:
  400 invalid_request  —— uid 格式非法
  401 unauthorized     —— 未登录
  404 not_found        —— 该用户不是我的粉丝（没有这条关系）
```

**语义要点**

- 只能移除**关注我的人**，不能移除我关注的人（那是取关，走 `DELETE /follow/{uid}`）；
- 目标 uid 与当前 uid 相同 → 400 invalid_request（自己不是自己的粉丝）；
- 删除不存在的关系返回 404，不要静默成功；
- 返回的 `followersCount` 必须是删除后的真实计数（同一次请求内查询，不要返回前端推算值）；
- 幂等性：重复删除第二次返回 404（因为关系已不存在），这是预期行为，不要改成 200。
