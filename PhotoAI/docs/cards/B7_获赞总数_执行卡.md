# B7 获赞总数接口执行卡

## 1. 目标

「我的」页统计栏那一格**「获赞」现在硬编码为 `—`**，因为没有任何接口提供它。本卡补上：

`GET /user/{uid}` 响应新增 **`likedTotal:N`** —— 该用户所有「展示」作品的 `likep` 之和。

同时本人视角也可用 `GET /user/info` 或直接 `GET /user/{自己的uid}` 拿到该值。

## 2. 现状（已核实）

- `mine.wxml:17`：`<text class="stat-number">—</text>` —— **写死的破折号**，没有绑定字段。
- `mine.js` 的 `loadStats()` 只请求 `/follow/following` 与 `/follow/followers` 取 `total`。
- `GET /user/{uid}` 已返回 `worksCount / followingCount / followersCount / followed / showFavorites / showLikes`（B5），**没有 `likedTotal`**。
- 数据现状：300 个用户，46 件展示作品，`likep` 合计 5801，`likep` 与 `liketable` 完全一致。

## 3. 改动

### 3.1 SQL

`Backend/src/main/resources/mapper/UserMapper.xml` 的 `homeProfile` 查询里追加一列：

```sql
(SELECT COALESCE(SUM(p.likep),0) FROM pwork p WHERE p.uid = u.uid AND p.wstatus='展示') AS likedTotal
```

口径：**只统计展示作品**的 `likep` 之和；`pwork.likep` 已与 `liketable` 记录数一致，直接求和即可，不要再去 `COUNT(liketable)`（会漏掉已删除作品的历史点赞语义差异）。

### 3.2 Service

`UserServiceImpl.home(...)` 的返回 `data` 里追加：

```java
data.put("likedTotal", state 或查询结果);   // 必须是 Long/数字，不是字符串
```

若 `homeProfile` 已把该列映射进实体/Map，直接取；否则用单独的聚合查询（二选一，在回报里说明选了哪种）。

不改文档（由调用方统一更新）。
