# B8 关系可见性与他人关系列表执行卡

## 1. 目标

让「关注列表 / 粉丝列表」也能设置是否对他人可见，并支持**查看他人的**关注/粉丝列表：

1. `GET /user/{uid}` 追加 `showFollowing` / `showFollowers`；
2. 新增 `GET /user/{uid}/following`、`GET /user/{uid}/followers`（受可见性控制）；
3. `PUT /user/privacy` 从 2 个字段扩展到 **4 个**。

## 2. 数据层（已完成，不要改表）

```sql
ALTER TABLE user
  ADD COLUMN vis_following TINYINT(1) NOT NULL DEFAULT 1,
  ADD COLUMN vis_followers TINYINT(1) NOT NULL DEFAULT 1;
```
现有 300 个用户全部默认 `1`（可见）。

## 3. 现状（已核实）

- 已有 `GET /follow/following`、`GET /follow/followers` —— **只查本人**（`@RequestAttribute uid`）。
- `GET /user/{uid}` 已返回 `showFavorites` / `showLikes`（B5），**没有** `showFollowing` / `showFollowers`。
- `PUT /user/privacy` 目前只接受 `visFavorite` / `visLike` 两个布尔（B5）。
- **已知前端 bug（本卡不修，F20 修）**：他人主页点「关注」数字，跳的是自己的关注列表，因为 relation 页只查本人。

## 4. 接口定义

### 4.1 `GET /user/{uid}` 追加两个字段

```
showFollowing = (vis_following=1 OR 请求者uid==目标uid)   // 本人恒 true
showFollowers = (vis_followers=1 OR 请求者uid==目标uid)
```

### 4.2 `GET /user/{uid}/following`

```
权限：登录
Q: page(默认1,≥1)、size(默认10,1–50)
响应: { list: FollowUser[], total: N }
可见性: 目标用户 vis_following=0 且 请求者≠目标 → 403 forbidden
404: 目标用户不存在
FollowUser 字段与现有 /follow/following 完全一致
```

语义：**目标用户关注的人**（`follow.uid=目标uid`），按 `follow.ct DESC, fid ASC`。

### 4.3 `GET /user/{uid}/followers`

同上，取 `follow.tuid=目标uid`，受 `vis_followers` 控制。

### 4.4 `PUT /user/privacy` 扩展

```
B: { visFavorite:bool, visLike:bool, visFollowing:bool, visFollowers:bool }
响应: 四个字段全部回显
规则: 四个字段**必须全部存在且为布尔**，缺任何一个或类型不对 → 400 invalid_request
      只改当前登录用户，不接受 body 里的 uid
```

## 6. 实现要点

1. 两个新列表返回的字段结构必须与 `/follow/following`、`/follow/followers` **完全一致**（复用同一套投影/映射），不能多也不能少。
2. 可见性 403 只在「目标关闭 + 请求者不是本人」时触发；本人看自己永远 200。
3. `total` 与列表同一 WHERE 条件。
4. 排序必须带主键兜底（`fid ASC`）。
5. 不得输出 `pwd` / `openid` / `pnum` 等敏感列。
6. 既有 `GET /follow/following`、`/follow/followers`（本人）语义保持不变。
