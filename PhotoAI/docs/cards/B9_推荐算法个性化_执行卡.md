# B9 推荐算法个性化与匿名轮转执行卡

## 1. 目标

`GET /pwork/list?tab=recommend` 目前是「时间衰减热度」，与 `hot` 前 10 重合 7/10，区分度不足。改成两条分支：

1. **登录用户**：按该用户的**分类偏好**加权 —— 他常点赞/收藏的分类，作品排更前；
2. **匿名用户**：**分类轮转**（每个分类各取第 1 名，再取第 2 名…），保证结果覆盖多个分类，且**不随机、分页稳定**。

`latest` 与 `hot` 的行为**完全不变**。

## 2. 现状（已核实）

- `WorkQueryMapper.xml` 的 `<choose>` 已有 `recommend` / `hot` / `otherwise` 三段；`recommend` 当前是：
  ```sql
  (COALESCE(p.likep,0)*2 + COALESCE(p.votecount,0)*5 + COALESCE(p.viewcount,0)/10.0)
  / SQRT(TIMESTAMPDIFF(HOUR, p.cwtime, NOW()) + 1) DESC, p.pid ASC
  ```
- `GET /pwork/list` 目前**匿名**，不解析 token（`@RequestParam` 只有 tab/category/page/size）。
- 数据现状：46 件展示作品分布在 8 个分类（夜景 8 / 街拍 7 / 建筑 6 / 微距 6 / 人像 5 / 黑白 5 / 纪实 5 / 风光 4）。
- 演示用户偏好不同，可用于验证：`6dae…`（街拍 4、夜景 3）、`49b43…`（夜景 5、街拍 3）。
- MySQL 8.0，支持窗口函数与 CTE。

## 3. 改动

### 3.1 列表接口解析可选身份

`PworkController.list(...)` 增加可选 token 解析（**参照 B1 详情接口的既有做法**，不要自己发明新机制）：

- 无 token → `viewerUid = null`，**不报错**
- **带无效 token → 401 `unauthorized`**（拦截器的既有行为，保持不动）：
  无效凭证不得静默降级为匿名，否则用户会以为自己登录着却看到匿名内容
- 有效 token → `viewerUid = 令牌里的 uid`
- 把 `viewerUid` 透传给 `workQueryService.list(...)`

`/pwork/list` 仍然**匿名可访问**，这只是"有身份就个性化"，不是收紧权限。

### 3.2 登录用户的 recommend

```
score = 时间衰减热度 × (1 + 2 × 该用户在该分类的互动占比)
互动占比 = 该分类下我的互动数 / 我的总互动数
互动 = liketable(uid=我, targettype='帖子') + favorite(uid=我)，按作品的 pcid 归类
```

SQL 形状（在 `recommend` 分支里用 LEFT JOIN 聚合，`ORDER BY` 用 `score DESC, p.pid ASC`）：

```sql
LEFT JOIN (
    SELECT pcid, c, SUM(c) OVER () AS total
    FROM (
        SELECT p2.pcid AS pcid, COUNT(*) AS c
        FROM liketable l2 JOIN pwork p2 ON p2.pid = l2.targetid
        WHERE l2.uid = #{viewerUid} AND l2.targettype = '帖子'
        GROUP BY p2.pcid
        UNION ALL
        SELECT p2.pcid AS pcid, COUNT(*) AS c
        FROM favorite f2 JOIN pwork p2 ON p2.pid = f2.pid
        WHERE f2.uid = #{viewerUid}
        GROUP BY p2.pcid
    ) parts
    GROUP BY pcid
) uf ON uf.pcid = p.pcid
```

排序表达式：

```sql
( <时间衰减热度> ) * (1 + 2 * COALESCE(uf.c, 0) / NULLIF(uf.total, 0)) DESC, p.pid ASC
```

- 用户**没有任何互动**时 `uf.total` 为 NULL → 权重退化为 1，等于纯热度（冷启动，符合预期）；
- 必须用 `COALESCE`/`NULLIF` 防除零，**不得让 SQL 报错或返回空列表**；
- 分页稳定：权重是确定的，`pid ASC` 兜底。

### 3.3 匿名用户的 recommend（分类轮转）

用窗口函数给每个分类内的作品排名，再按 `(rank, pcid)` 排序。**这样前 N 条会轮流覆盖各个分类。**

```sql
-- 在直接查询不可行时，可用派生表/CTE 包一层
SELECT * FROM (
    SELECT <Work 全部列>, ROW_NUMBER() OVER (
        PARTITION BY p.pcid ORDER BY <时间衰减热度> DESC, p.pid ASC
    ) AS rn
    FROM pwork p LEFT JOIN user u ON u.uid = p.uid LEFT JOIN pclist c ON c.pcid = p.pcid
    WHERE p.wstatus = '展示'
) ranked
ORDER BY ranked.rn ASC, ranked.pcid ASC
LIMIT #{size} OFFSET #{offset}
```

要求：

- 前 10 条**至少覆盖 5 个不同分类**（当前数据下会覆盖 8 个）；
- `total` 仍是展示作品总数，与排序无关；
- 分页稳定：`ORDER BY rn, pcid` 完全确定，**第 1 页与第 2 页不得有重复 pid，两页合起来不得漏项**；
- `pcid` 为 NULL 的作品作为一个独立分组参与轮转，不得丢弃。

### 3.4 category 过滤

若请求带 `category=xxx`，两条分支都**只在那个分类内**排序：

- 登录：正常个性化加权（该分类内）
- 匿名：单分类轮转退化为该分类内的热度排序（`rn` 全为 1、2、3…，等价于热度序）
