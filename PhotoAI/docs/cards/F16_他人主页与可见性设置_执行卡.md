# F16 他人主页与可见性设置执行卡

## 1. 目标

让用户能从任何地方点头像进入对方主页，并在自己的主页设置里控制收藏/喜欢的可见范围：

1. **详情页头像可点** → 进 `pages/userDetail/userDetail?uid=xxx`；
2. **`userDetail` 页重写**：头像 + 昵称 + bio + 关注按钮 + 三项统计 + 三个 tab（作品 / 收藏 / 喜欢）；
3. **tab 按可见性显示**：对方关闭了收藏/喜欢，就**不显示对应 tab**（不显示空列表）；
4. **我的页「设置」tab 加两个开关**：收藏可见、喜欢可见，改完立即生效。

作品 tab 永远只显示对方的「展示」作品（后端已保证）。

依据：`docs/cards/B5_他人主页与可见性_执行卡.md`（后端接口契约）。

## 2. 接口契约（B5 提供）

```
GET  /user/{uid}                    匿名
  → { uid, uname, avatar, bio,
      worksCount, followingCount, followersCount,
      followed, showFavorites, showLikes }

GET  /user/{uid}/works?page&size    匿名 → { list: Work[], total }
GET  /user/{uid}/favorites?page&size 匿名 → { list, total } | 403 forbidden
GET  /user/{uid}/likes?page&size     匿名 → { list, total } | 403 forbidden

POST   /follow/{uid}                登录 → { following: true, ... }
DELETE /follow/{uid}                登录 → { following: false, ... }
PUT    /user/privacy                登录，B { visFavorite: bool, visLike: bool }
GET    /user/info                   登录 → 本人信息（已有）
```

Work 字段与 `/pwork/list` 一致：`pid uid wtitle wdesc vurl viewcount votecount wstatus cwtime likep uname avatar pcid pcname realLikeCount`。

## 3. 改动一：详情页头像可点

文件：`pages/workDetail/workDetail.wxml`

作者头像（第 13、14 行附近，`.author-avatar`）包一层或直接加：

```xml
bindtap="goAuthor" data-uid="{{work.uid}}" role="button" aria-label="查看作者主页"
```

`pages/workDetail/workDetail.js` 新增：

```js
/**
 * 打开作者主页；作者 uid 缺失或是自己时分别退化为不跳转/进我的页。
 * @param {{currentTarget:{dataset:{uid:string}}}} e - 头像点击事件
 * @returns {void}
 */
goAuthor(e) {
  const uid = e.currentTarget.dataset.uid
  const me = app.globalData.uid
  if (!uid) return
  if (uid === me) { wx.switchTab({ url: '/pages/mine/mine' }); return }
  wx.navigateTo({ url: '/pages/userDetail/userDetail?uid=' + encodeURIComponent(uid) })
}
```

**注意**：评论区头像（`.comment-avatar`）也要能点——同样的 `bindtap="goAuthor"` 与 `data-uid="{{item.uid}}"`。如果评论区取不到 uid 就不要加。

## 4. 改动二：重写 `pages/userDetail/*`

### 4.1 结构

```
顶部：返回按钮（view，不用 button）+ 右侧「更多」不实现
头部：头像 128rpx 圆形 + 昵称 34rpx 粗体 + bio 24rpx 灰（无 bio 时不占位）
      右侧：关注 / 已关注 按钮（view，胶囊，粉色描边）
统计行：作品 N ｜ 关注 N ｜ 粉丝 N   （三个都可点：作品切 tab，关注/粉丝跳 relation 页）
tab 行：作品 / 收藏 / 喜欢（按 showFavorites / showLikes 决定是否渲染）
列表：双列瀑布流或单列卡片——**沿用 `pages/mine/mine.wxml` 里作品卡片的样式与结构**，保持一致
```

### 4.2 行为

- `onLoad(options)` 取 `uid`，并行拉 `GET /user/{uid}` 与 `GET /user/{uid}/works`
- 切 tab 懒加载：第一次切到收藏/喜欢才请求
- 三个列表各自的 `page/total/loading/error/noMore`，**互相独立**，切 tab 不重置彼此
- 卡片点击 → `/pages/workDetail/workDetail?pid=`
- 作品为空 → 「TA 还没有发布作品」
- 收藏/喜欢为空 → 「TA 还没有公开的收藏」/「TA 还没有公开的喜欢」
- 403（对方关闭可见）→ 该 tab **不渲染**（以 `showFavorites/showLikes` 为准，正常不会走到 403；若走到就显示「不可见」而不是报错）
- 关注按钮：未关注显示「关注」，已关注显示「已关注」；点击调 `POST/DELETE /follow/{uid}`，成功后按接口返回更新，**不做乐观更新**
- 未登录点关注 → 走项目既有 `app.requireLogin` 流程
- 自己看自己（`uid === app.globalData.uid`）→ 关注按钮换成「编辑资料」，跳 `pages/userEdit/userEdit`
- 返回按钮 → `wx.navigateBack`，无栈时回首页

### 4.3 分页与竞态

- 分页参数 `page` 从 1 开始、`size=10`
- 每个列表独立 `_requestId`，丢弃过期响应
- 触底加载与下拉刷新按项目既有写法（参考 `pages/mine/mine.js`）

## 5. 改动三：我的页设置加开关

文件：`pages/mine/mine.wxml` 的 `tab === 'settings'` 分支、`pages/mine/mine.js`、`pages/mine/mine.wxss`

在设置列表里加两行：

```
收藏可见    [switch]   ← 说明文字「开启后别人能在你的主页看到你的收藏」
喜欢可见    [switch]   ← 说明文字「开启后别人能在你的主页看到你的喜欢」
```

- 初始值来自 `GET /user/info` 返回的 `visFavorite` / `visLike`（若接口暂未返回该字段，先用 `true` 并在回报里标注）
- 切换时调 `PUT /user/privacy`，body `{ visFavorite, visLike }`（**两个字段都要带**，另一个保持当前值）
- 成功后 toast「已更新」；失败则**把开关拨回原值**并提示
- 用 `<switch>` 组件（微信原生），`bindchange`，`disabled` 防连点
