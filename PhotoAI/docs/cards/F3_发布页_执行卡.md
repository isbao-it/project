# F3 发布页执行卡

## 1. 目标与用户路径

目标：登录作者完成选图上传、查看安全 EXIF、填写资料、发布为待审核，并在我的确认结果。
步骤：发布 tab → 选 JPEG/PNG → 上传 → 显示安全图片与六项 EXIF → 填标题/描述/分类 → 提交 → 我的待审核列表。
依据：`../接口冻结_v1.md` v1.1 §1.3、§1.6、§2；依赖 F1 的 workList 发布占位、201 成功判断及 mine 列表。
沿用已注册的 pages/workList/workList 作为发布页，不新增路由，不修改 app.json.pages。
上传成功不等于发布成功；仅 POST /pwork 返回 201+ok 且 status=待审核后显示发布成功。

## 2. 页面/文件清单

以下路径相对 `WeChat Mini Program/pg/`；新增文件：无；仅允许修改下列文件。
- 修改 `pages/workList/workList.wxml`：选图/预览、上传状态、EXIF 只读区、标题/描述、分类选择及发布按钮。
- 修改 `pages/workList/workList.js`：登录守卫、分类加载、wx.uploadFile、信封解析、发布状态和 mine 跳转。
- 修改 `pages/workList/workList.wxss`：表单、图片、EXIF、失败提示和按钮禁用样式。
- 修改 `pages/workList/workList.json`：发布页局部标题与声明。
上传用 multipart 字段 file，携带 Bearer token；wx.uploadFile 的字符串响应须解析并校验 HTTP 和 code。
只在上传成功且 exifStripped=true 后保存 url 与六项 exif；换图先清旧值，取消选图则保留原有效选择。
分类未加载/为空、上传中/失败、发布中均不能提交；连点只发一次，失败恢复按钮与输入。
发布体只组装 title/desc/imageUrl/categoryId 及可选 exif；成功后清表单并 switchTab 到 mine，由其 onShow 刷新。

## 3. 依赖的后端接口

- GET `/category/list`：无参数；data.list[].pcid/pcname/count；categoryId 取选中 pcid，不用名称代替 ID。
- POST `/upload/work`：multipart file，单张 JPEG/PNG、≤10MB；data.url/exif/exifStripped（必须 true）。
- POST `/pwork`：JSON title（非空白、≤100）、desc（≤255、允许空串）、imageUrl（安全上传地址、≤255）、categoryId（必填字符串 ID）、exif（选填对象）；成功 HTTP 201，data.pid/status=待审核。
EXIF 白名单 focal/aperture/shutter/iso/lens/camera，上传后只读回传；不传 GPS/序列号或原始元数据，不新增 uploadId。
上传失败识别 400/401/413/422；发布失败识别 400/401/422 content_rejected/503 service_unavailable；网络失败单独提示，不自动重发发布。
mine 列表复用 F1 的 GET /pwork/mine，本卡不另写列表请求；仅两次写请求均成功才走完整链路。

## 4. 人眼验收清单

- [ ] 游客点击发布并完成微信登录 → 跳转及表单 → 返回发布页，无 token 时不上传、不提交。
- [ ] 选择合法 JPEG/PNG → 请求、图片与 EXIF → file 上传一次，携带 token，展示服务器 url 和六项安全参数。
- [ ] 上传无 EXIF 图片或缺部分字段图片 → 参数区 → 缺项明确显示“暂无”，无 undefined，不伪造参数。
- [ ] 取消选图，再尝试超10MB、损坏或非支持图片 → 表单与提示 → 取消不报错，非法图片提示原因，不进入可发布状态。
- [ ] 上传中连点发布、上传后换图并令新上传失败 → 请求及旧数据 → 不发发布请求，不复用上一张 url/exif，失败后可重选。
- [ ] 留空标题/分类、输入超长标题或描述，再改为合法值 → 校验及网络 → 非法时不提交；描述空串合法，分类按 pcid 提交。
- [ ] 在开发者工具令上传返回错误码、无效 JSON 或 exifStripped=false → 提示与发布按钮 → 明确提示上传失败且禁止发布，无假成功。
- [ ] 连点提交合法表单 → 发布请求及我的 → 仅一次 POST，201+ok 后提示待审核，mine 可见同一 pid；提交体无 uid/status/计数。
- [ ] 分别制造 401、422 内容拒绝、503、断网 → 提示与输入 → 登录过期引导重登；其余保留表单并可手动重试，不自动当成功。
- [ ] 发布后用游客刷新首页并尝试该 pid 公共详情 → 列表与详情 → 待审核作品不公开，详情为404；上传成功本身不产生作品。

## 5. 禁止行为

- 不得改后端 `src/main`、任何既有测试；不得删旧页面；不改 tabBar 之外全局配置，本卡也不改 tabBar。
- 不修改 request.js 或 mine（由 F1 提供）；不新增依赖/组件，不实现作品编辑、删除、审核、向量编码或假安全检查。
- 不接受客户端自定审核状态/作者，不回传 GPS/序列号，不用本地路径代替服务器 imageUrl，不把上传成功当发布成功。
- 不使用 git，不修改上列之外文件；真实上传/发布/微信或人眼链路未跑须标注未验证。
