# F5 后台审核联调执行卡

## 1. 目标与用户路径

目标：用真实待审核作品完成后台通过/带理由驳回，并让作者在 mine 看到最新状态和驳回原文。
步骤：作者经 F3 发布 → 管理员登录 → 后台首页“作品审核” → 待审分页 → 通过或填写理由驳回 → 作者刷新我的 → 游客核对公开可见性。
依据：`../接口冻结_v1.md` v1.1 §1.2 后台登录、§1.3 mine/公开读取、§1.4 审核；依赖 F1、F2、F3。
现有 audit.html 已接待审/通过/驳回 API，本卡只读联调，不重建页面；真实接口缺口记录后交后端处理。
冻结契约区分：通过无请求体、reason=null；驳回必须传1–200字且非空白的 reason，不给通过接口加理由字段。

## 3. 依赖的后端接口

- POST `/user/login`：沿用现有后台登录页；form-urlencoded pnum（11位数字）/pwd；data.token/role=管理员/uname/uid，不改为 JSON。
- GET `/admin/work/pending`：管理员；query page/size；data.list/total；每项 pid/vurl/wtitle/wdesc/uname/uid/cwtime，固定待审核。
- PUT `/admin/work/{pid}/approve`：管理员，无请求体；data.pid/status=展示；非待审核为409。
- PUT `/admin/work/{pid}/reject`：管理员；JSON reason（必填、1–200字、非空白）；data.pid/status=已驳回；非待审核为409。
- GET `/pwork/mine`：作者 token；query status（待审核/展示/隐藏/已驳回，可省略）、page/size；data.list/total，每项 wstatus/reason。
- GET `/pwork/list`：游客；query tab=latest、page/size；data.list/total，仅展示作品，用于公开可见性核对。
- GET `/pwork/{pid}`：游客；data.work/exif/author；非展示作品404，用于详情可见性核对。
共用：Bearer token；HTTP 与字符串 code 联合判定，成功 code='ok'；ID 不转数字，分页不用 pageNum/pageSize。

## 4. 人眼验收清单

- [ ] 作者发布至少两件带唯一标题的作品，管理员打开审核入口 → 列表及 GET 请求 → 对应真实 pid 均在待审核列表，读取 data.list/total，无静态替代。
- [ ] 翻页、切每页条数、刷新至空结果 → 表格与页码 → 分页参数合法，空态明确；末页最后一项审核后回到有效页。
- [ ] 对其中一件点击通过 → 请求、待审列表和作者 mine → PUT 无 body，成功展示且从待审移除，mine 状态展示、reason 无值。
- [ ] 另一件输入空白或201字理由再驳回 → 提示与请求 → 明确校验失败，不发审核请求；改为1–200字原文可提交。
- [ ] 填合法理由驳回，再由作者切回/下拉 mine → 两端反馈及作品项 → 待审移除，作者看见“已驳回”和同一条完整理由。
- [ ] 使用含换行及 HTML 字符的合法理由并刷新 → 后台与 mine 文本 → 原文可读、长文本换行，标签不执行，不残留其他作品理由。
- [ ] 同时打开两个审核窗口，对同一 pid 先审核再从旧窗口操作 → 提示与状态 → 重复请求409，显示已审核并可刷新，不提示成功、不覆盖前次结果。
- [ ] 以普通账号/过期 token 请求审核，再恢复管理员登录 → 权限提示与按钮 → 分别403/401，无审核成功反馈；恢复后能刷新，网络失败可重试。
- [ ] 游客刷新首页并打开已通过、已驳回、仍待审核的 pid → 列表及公共详情 → 只通过作品可见，其余不入列表且详情404；mine 仍能按状态找到本人作品。
