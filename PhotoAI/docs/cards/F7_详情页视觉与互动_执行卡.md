# F7 详情页视觉与互动执行卡

## 1. 目标与用户路径

目标：把作品详情页按 `docs/preview/photoai_mockup.html` 第 ② 屏重做视觉，并**一次性接上**评论、点赞、收藏、关注、同款机位、分享六个真实能力（后端接口均已就绪，前端 card05/06/07 目前是空壳）。

用户路径：首页点卡片 → 详情页 hero 大图 → 标题/副标题/EXIF 摘要 → 作者行（关注）→ 四连操作（赞/藏/评/分享）→ 同款机位 → 评论区（列表 + 发评论）→ 返回。

依据：`docs/preview/photoai_mockup.html` 第 63–85 行（`.detail-hero` / `.detail-body` / `.d-title` / `.d-sub` / `.author` / `.follow` / `.actions` / `.cmt`）；`docs/接口冻结_v1.md` §1.3（#6）、§1.5（#20–24）、§1.6（#12、#26–27）、§1.7（#29–30）；`docs/cards/F2_画廊与详情_执行卡.md` §3。

## 2. ⚠️ 已知接口缺口（实现必须按此处理，不得自行改后端）

对 `p-demo-audit` 实测 `GET /pwork/{pid}` 的响应：
```json
{"data":{"work":{"pid","uid","wtitle","wdesc","vurl","viewcount","votecount","wstatus","cwtime","likep","uname","avatar","pcname","realLikeCount"},"exif":null,"author":{"uid","nickname","avatar"}}}
```
**没有** `liked` / `favorited` / `following` / `favoriteCount` 字段，冻结契约里也没有「查询我是否已赞/已藏」的接口。因此：

- 点赞、收藏、关注三个按钮 **初始一律渲染为未激活态**，不得假装知道状态；
- 首次点击后，以接口返回的 `liked` / `favorited` / `following` 作为真值；
- 重复点击是幂等的（POST 重复成功、DELETE 重复成功），不会报错；
- **收藏数初始不显示**，只在收到 `POST/DELETE /favorite/{pid}` 的 `count` 后才显示；
- 点赞数初始用 `work.likep`，每次点赞/取消后同步接口返回的 `count`；
- 关注后不显示粉丝数变化（接口返回 `followers`，可显示在作者行副标题里，非必需）。

## 4. 页面结构（自上而下）

1. **hero 图**：全宽、`height:500rpx`、`mode="aspectFill"`、点击 `previewImage` 预览大图。无图时显示 `#F6F7F8` 底 + 「暂无图片」。
2. **悬浮返回按钮**：绝对定位在 hero 左上角，距顶 `statusBarH + 12px`，`56rpx` 圆形半透明黑底 + 白色 `‹`。
3. **正文区**（白底、`border-radius:24rpx 24rpx 0 0`、`margin-top:-24rpx` 压住图底）：
   - 标题：`34rpx`、`#18191C`、`font-weight:700`、最多两行。
   - 副标题：`22rpx`、`#9499A0`，格式 `分类名 · 日期 · f/光圈 快门 ISO`，缺项自动省略（用 ` · ` 连接，不出现「null」「undefined」「—」堆叠）；`cwtime` 取前 10 位作为日期。
   - 作者行：`64rpx` 圆形头像（无头像用渐变占位）+ 名字 `28rpx` + 右侧「关注」按钮（`120rpx × 56rpx`、`border-radius:28rpx`、粉色底白字；已关注时改为白底粉字 + `1rpx solid #FB7299`，文案「已关注」）。
4. **四连操作**：横向 `justify-content:space-around`，每项 `icon + 数字`（`24rpx`、`#61666D`）：
   - 点赞 `♥` + `work.likep`；激活态粉色 `#FB7299`
   - 收藏 `☆` + 计数（初始无数字，见 §2）；激活态粉色
   - 评论 `💬` + 评论总数（来自 `comment/list` 的 `total`）
   - 分享 `↗`，触发 `wx.showShareMenu` 已由 `onShareAppMessage` 支持；点击时调用 `wx.showToast({title:'请点右上角分享'})` 或直接无动作，二选一，**不得伪造分享成功**
5. **同款机位行**：`📷 同款机位 · 参数相近的作品 ›`，右侧箭头；下方横向 `scroll-view` 展示同款作品缩略图（`180rpx` 宽、圆角 `16rpx`、标题一行省略），点击跳对应详情。**同款列表为空时整行隐藏**（不留空洞）。
6. **评论区**：
   - 标题「评论 N」（N 为 total）。
   - 评论项：`56rpx` 头像 + 昵称 `26rpx` + 内容 `28rpx`（支持换行）+ 时间 `22rpx` 灰；自己的评论右侧显示「删除」（`cid` 与当前登录 uid 匹配时），点击二次确认后 `DELETE`。
   - 空态：显示「还没有评论，来说两句」。
   - 输入行（固定在评论区底部，非悬浮）：`input` 占位「说点什么…」+ 「发送」按钮；未登录时点击输入框跳登录（`app.requireLogin`）。
   - 发送中禁用按钮防重复提交；成功后清空输入、把新评论插到列表顶部并 `total+1`。
7. **状态区**：加载中显示骨架或「作品加载中…」；404/失败显示原有文案 + 重试按钮 + 返回按钮（保留现有逻辑）。

## 6. 接口调用表（路径与字段以此为准，均已实测）

| 能力 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 详情 | GET | `/pwork/{pid}` | 返回 `work/exif/author`；`author.uid` 存在，可用于关注 |
| 评论列表 | GET | `/comment/list?pid&page&size` | 返回 `{list,total}`；每项字段：`pid/cid/uid/content/createdAt/nickname/avatar`（注意是 `content` 不是 `comcontent`） |
| 发评论 | POST | `/comment` | body `{pid, content}`，1–500 字；返回 `{cid}` |
| 删评论 | DELETE | `/comment/{cid}` | 仅作者或管理员；403/404 需给中文提示 |
| 点赞 | POST/DELETE | `/like/{pid}` | 返回 `{liked, count}` |
| 收藏 | POST/DELETE | `/favorite/{pid}` | 返回 `{favorited, count}` |
| 关注 | POST/DELETE | `/follow/{uid}` | 返回 `{following, followers}`；关注自己返回 409 |
| 同款 | GET | `/pwork/similar/{pid}?limit=6` | 返回 `{list}`（不带 total）；空数组时隐藏整块 |

所有请求走 `utils/request.js` 的 `request(path, method, data)`；错误提示沿用项目现有方式，**不得把后端报文原文直接弹给用户**。

## 7. 人眼验收清单

- [ ] 进入详情 → 顶部 → 无原生导航栏；hero 大图通栏，左上角有悬浮返回按钮，**不遮挡图片关键区域**。
- [ ] 标题下方 → 副标题为「分类 · 日期 · 参数」形式，缺 EXIF 时**不出现 null/undefined/连续的 ` · `**。
- [ ] 作者行 → 头像/名字/关注按钮；点关注 → 变「已关注」且样式切换；再点 → 变回「关注」。
- [ ] 四连 → 点赞后数字 +1 且变粉；再点 -1 且变灰；**收藏初始无数字，点后出现数字**。
- [ ] 评论 → 列表按时间倒序；自己的评论有「删除」；删除后列表与计数同步减少。
- [ ] 发评论 → 输入框空内容时不发请求；发送成功后新评论出现在顶部，输入框清空。
- [ ] 未登录 → 点赞/收藏/关注/发评论 → 跳登录页，**不出现接口 401 原文弹窗**。
- [ ] 同款 → 有数据时显示横向缩略图并可跳转；**无数据时整块不出现**（不留空白行）。
- [ ] 非展示或不存在 pid → 显示不可访问提示 + 返回按钮，无旧数据残留。
- [ ] 返回 → 回到首页且列表位置/筛选保持原样。
