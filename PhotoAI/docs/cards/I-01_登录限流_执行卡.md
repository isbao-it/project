# I-01 登录接口限流 · 实现卡

## 0. 终审三块速读

**验收 GWT**
- **G**：已登录 Redis（真实例），`POST /user/login` 用错密码连发 5 次
- **W**：第 6 次再发同 IP 请求
- **T**：返回 **HTTP 429** + body `code:429`/`msg:"too_many_requests"` + 头 `Retry-After`（1–60）；`/user/info` 连发 6 次仍不 429；窗口过后恢复

**用户手测（≤5 分钟）**：见 §6 三条 curl，第 6 次必须 429、等 60 秒后恢复、其他接口不受影响

**禁止行为**：改 T-01 冻结测试 / 加 xfail-skip / 特判测试环境 / 改鉴权逻辑 / 动 DB schema / git 操作

## 1. 目标

给 `POST /user/login` 加**按客户端 IP 的固定窗口限流**（默认 5 次 / 60 秒），超限返回真实 429；Redis 故障时**放行**（fail-open）并记 WARN。

## 4. 契约（钉死）

| 项 | 值 |
|---|---|
| 生效范围 | **仅** `POST /user/login` |
| 维度 | `request.getRemoteAddr()`（**不读** `X-Forwarded-For`） |
| 阈值/窗口 | `ratelimit.login.max`（默认 5）、`ratelimit.login.window-seconds`（默认 60） |
| Redis 键 | `rl:login:{ip}`；首次 `INCR` 后设 `EXPIRE window-seconds` |
| 超限 | HTTP **429**；body 用现有 `AjaxResult.error(429, "too_many_requests")`；头 `Retry-After` = 键剩余 TTL（整数秒，最小 1） |
| Redis 不可用 | **fail-open**：`try/catch` 连接异常 → 放行 + `log.warn` |
| 注册顺序 | 在 `AuthInterceptor` **之前**（登录爆破不该先过鉴权） |

## 5. 实现要求

1. `RateLimitInterceptor implements HandlerInterceptor`，`preHandle` 里只处理 `POST /user/login`，其余直接 `return true`。
2. 计数用 `StringRedisTemplate.opsForValue().increment(key)`；**等于 1 时**才 `expire(key, window)`（避免每次刷新 TTL）。
3. 超限时 `response.setStatus(429)`，写 JSON（`Content-Type: application/json;charset=UTF-8`），并 `setHeader("Retry-After", ...)`，`return false`。
4. Redis 异常整体 `catch (Exception e)` → WARN + `return true`（fail-open）。**不得**吞掉其他异常掩盖 bug（catch 里打全栈）。
5. 配置用 `@Value("${ratelimit.login.max:5}")` 形式，**默认值必须与契约一致**（测试会用 `window-seconds=2` 覆盖）。
6. `docker-compose.yml` 只写 redis：`image: redis:7-alpine`、`ports: ["6379:6379"]`、`restart: unless-stopped`。**不要**顺手加 mysql/backend（本卡不做）。
7. 不动 `AuthInterceptor` 的鉴权逻辑；不改旧错误契约（登录失败仍是 200 + `code:401`）。

```powershell
1..6 | % { curl.exe -s -o NUL -w "%{http_code}`n" http://localhost:8082/user/info }
```
