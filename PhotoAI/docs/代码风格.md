# 代码风格（以现有代码为准）

> **第一原则：新代码要和仓库里已有的代码长得一样。** 不是"更规范的写法"，是"同一个人的写法"。
> 偏离任何一条 = 停手报告，不许自行"改良"。

## 1. 文件与缩进

| 项 | 规则 | 证据 |
|---|---|---|
| 编码 / 换行 | **UTF-8 + CRLF** | `pworkController.java` 实测 |
| 缩进 | **4 空格**，不用 Tab | 现有全部 .java |
| 包结构 | `com.pg.{controller,service,service.impl,domain,entity,mapper,myutils,config,interceptor}` | 现有目录 |
| 类名 | **大驼峰 PascalCase**（`UserController`、`PworkService`、`UserServiceImpl`）。存量 **9 个**小写 Controller（`userController`、`pworkController` 等）由**卡 11 统一机械迁移**，卡内不得顺手改 | 用户 2026-10-18 定：按规范 |

## 2. 分层结构（照现有三件套，不引入新抽象）

```
controller/xxxController.java   ← 参数校验 + 调 Service + 返回 AjaxResult
service/XxxService.java         ← 接口
service/impl/XxxServiceImpl.java ← @Service + @Autowired + MyBatis-Plus
domain/Xxx.java                 ← 实体（@TableName/@TableId）
mapper/XxxMapper.xml            ← 复杂查询（resultMap + <where>）
```

- Controller **不写 SQL、不写事务**；Service 里做业务。
- **不引入**：DTO/VO 层、MapStruct、Lombok builder 链、自定义异常体系、`@RestControllerAdvice`（除非当卡明确要求）。
- 依赖注入用 **`@Autowired` 字段注入**（现有写法），不用构造器注入。

## 3. 注释（这是最显眼的风格）

```java
// ------------------- 分页条件查询 -------------------     ← 分段标题（照抄这个格式）

/**
 * 获取用户列表
 * @param pageNum 页码数，默认值为1
 * @param pageSize 每页条数，默认值为10
 * @return AjaxResult 包含分页信息和用户列表
 */
public AjaxResult userList(...) {

    param.put("uname", user.getUname());    // 添加用户名条件        ← 中文行尾注释
```

- **公共方法必须有 `/** */`**（说明 + `@param` + `@return`）
- **每个非平凡语句后面带中文行尾注释**，说明"这行在做什么"
- 复杂块前写**为什么**这么做（比如"先查重再插入，避免唯一键异常"）
- 魔法数字/阈值必须标来源（配置键或卡号）

## 4. 返回值与错误

- 统一 `AjaxResult`：成功 `AjaxResult.success(data)` / `AjaxResult.success(total, list)`；失败 `AjaxResult.error(code, "中文提示")`
- **新增接口按架构方案 §6**：HTTP 状态码与 `code` 同值（401/403/409/422/429/500/503）；旧接口（`/user/login` 等）保持原样不动
- 提示文案用**中文短句**，不拼英文、不带堆栈

## 5. 持久层

- 单表增删改查 → **MyBatis-Plus**（`LambdaQueryWrapper` / `getOne` / `updateById`），照 `userController`
- 多表/复杂查询 → **Mapper XML + resultMap**，照 `WorkDetailMapper.xml`
- 分页 → **PageHelper**（`PageHelper.startPage` + `PageInfo`），照 `userController.userList`
- **不写 `SELECT *`**（现有 `view_work_detail` 那条是历史写法，新代码列出字段）

## 6. 命名

| 对象 | 规则 | 例 |
|---|---|---|
| 表/字段 | 下划线小写 | `work_exif`、`focal_mm` |
| 实体属性 | 小驼峰，与列名对应 | `focalMm` |
| 接口路径 | 小写 + 复数/资源名 | `/pwork/list`、`/comment/list` |
| 配置键 | `kebab-case` | `ratelimit.login.max` |

## 7. 日志（用户 2026-10-18 定：按规范）

- **统一 SLF4J**（Spring Boot 2.4.5 已自带 `slf4j-api` + logback，无需加依赖）：

```java
private static final Logger log = LoggerFactory.getLogger(XxxController.class);
log.info("作品发布成功 pid={} uid={}", pid, uid);
log.warn("Redis 不可用，限流已放行 path={}", path);
log.error("建索引失败 pid={}", pid, e);      // 异常放最后一个参数，不拼 e.getMessage()
```

- **禁止 `System.out.println`**（存量 2 处：`userController:330`、`PgApplication:10`，由卡 11 清理）
- **禁止打印**：手机号、密码、openid、token、图片 URL 全串
- 占位符 `{}` 不拼字符串；异常作为最后一个参数传入

## 8. 禁止清单（出现即打回）

1. 重新格式化整文件 / 改 import 顺序 / 把 LF 改成别的
2. **在业务卡里顺手改旧类名或替换旧日志**（统一由卡 11 机械迁移，避免大 diff 与冲突）
3. 引入本文件 §2 列的"不引入"项
4. 给旧方法补 DTO/异常体系等"顺手重构"
5. 中文注释写成英文、或删掉别人的注释
6. 用 `var`、Stream 链式一大坨、三目嵌套超过 1 层
