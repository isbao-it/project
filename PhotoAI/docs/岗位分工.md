# 岗位分工（三岗 + 终审）

> **一句话**：**出题的不写实现，写实现的不改题，验收的既不出题也不实现。**
>
> **铁律（用户 2026-10-21）**：同一张卡里，**测试代码与实现代码必须由不同工人交付**。不许"卡内 TDD"把两件事交给同一个人——卡 01 就是这么漏掉 V-01 路径绕过漏洞的。

| 岗 | 谁 | 只做什么 | **绝对不能做** |
|:-:|---|---|---|
| **T 测试岗** | Qoder CLI（`DeepSeek-Flash`） | 从 A-xx 派生 T-xx、写**冻结测试**、跑红态、补边界与负向用例 | 改 `src/` 任何文件；按"跑一遍看输出"反推断言；为让测试绿而放松断言 |
| **I 实现岗** | Codex CLI（`gpt-6.1-sol` + `high`） | 读**只读**冻结测试，改代码让它绿 | 改测试 / 夹具 / 收集配置；xfail/skip 吞失败；特判测试环境；绕过真入口 |
| **V 验收岗** | Hermes | 复跑三证据、diff 范围、全量+ruff、审定题目对不对 | 写实现；写测试（只审） |
| 终审 | 用户 | 看 **GWT / 手测项 / 禁止行为** 三块 → `#审核通过` | — |

## 三条硬规则

1. **时序：测试先于实现。** T 卡交付并冻结后，才派 I 卡。T 岗在写测试时**看不到实现**（Bug 卡则先写复现测试）。
2. **判定依据引 A-xx，不引实现。** 断言里的期望值必须能指回 A-xx 或卡面契约；**禁止**用"当前代码的输出"当期望值。
3. **权限只能事后检测。** Qoder 的 Write 无法限定路径 → 靠三件：派工单白名单、`--permission-mode accept_edits`、交付后 **diff 范围 + 冻结物增删改比对**。不得声称"事前隔离"。

## 风险与边界（诚实）

- **Flash 级模型容易只测 happy path**：T 岗产物必须过 Hermes 审定 + 定向故障检验，否则冻的是弱断言。
- **Qoder 免费额度限时（10/24 起不再 0 Credits）**：该岗位是**可选工人**，不写进流程硬依赖；到期换模型或换人（`-m` 改一下即可，岗位不变）。
- **Redis / MySQL 前置**：真实限流测试需要真 Redis（`docker run -d -p 6379:6379 redis:7-alpine`）与 MySQL80（`net start MySQL80`）。用内存假实现测限流 = 测不到真行为。
