## 一、每卡接口清单

### 1.1 表格记法与完整数据对象

- 表中响应列描述 `data`；外层固定为第二节的 `code/msg/data`。`null` 就是 JSON null，无请求字段写“无”。
- `P.uid/P.pid/P.cid` 是路径参数；`Q` 是 query；`B` 是 JSON body；`F` 是表单字段；`M` 是 multipart 字段。每项按“名称:类型，必填性，校验”书写。
- `ID` 是 JSON string；路径 uid 校验 `[A-Za-z0-9_-]{1,64}`，沿用基线；路径 pid/cid 和请求中的作品、分类 ID 校验 `[A-Za-z0-9_-]{1,36}`。存储 ID 长度不超过 36，绝不转 number。不存在且格式合法的资源返回 404。
- `page:int`：Q、选填、默认 1、必须 ≥1；`size:int`：Q、选填、默认 10、必须 1–50。所有分页接口都接受这两个参数，非整数或越界为 400；页码超出结果范围为成功空页。新接口不接受 `pageNum/pageSize` 作为别名。
- `N` 表示非负 JSON integer，服务端用 Long 承接计数和 COUNT，避免 `INT UNSIGNED` 超出 Java Integer 正数范围。`T` 是第二节的时间字符串。`?` 只表示该值可为 null，不表示字段可以消失。
- 下列对象是完整展开的字段集合；引用对象名即引用整行字段，禁止返回持久化实体额外属性。字段取值遵循第六节已拍板决议，不允许自行更换字段名。

**v1.2 受控扩展（B1）**

- `GET /pwork/{pid}`：请求携带有效令牌且令牌身份等于该作品 `pwork.uid` 时，允许返回非「展示」状态的作品详情；
  其余情况（匿名、无效令牌、非作者）仍只返回 `wstatus='展示'`，其它情况一律 404，与 v1.1 一致。浏览量自增遵循同一可见性条件。
- 新增 `PUT /pwork/{pid}/status`（登录、仅作者）：Body `status` 仅接受 `展示` / `隐藏`；
  只允许 展示↔隐藏 互切，当前为 待审核/已驳回 时返回 409，相同状态幂等返回 200，
  非本人作品或不存在返回 404，未登录 401，非法 status 400。

上传只返回服务器保存的安全图片地址；提取允许的六项后剥离 GPS、设备序列号，再对外提供图片，不回传原始 EXIF。**v1.1 为 POST /pwork 增加选填 exif 对象**，客户端可回传上传响应的六项；服务端重新校验，通过后用新建 pid 写 work_exif，不能把客户端回传当作可信原始元数据。不新增 uploadId。

exif 省略时不写 work_exif；传值必须是对象，null/数组/字符串为400。只投影 `focal/aperture/shutter/iso/lens/camera` 六字段，缺项按 NULL；单项可为 NULL。按现有列范围：focal 为正整数且 ≤32767mm，iso 为正整数且 ≤32767（SMALLINT）；aperture 为正数且 ≤99.9、至多1位小数（DECIMAL(3,1)）；shutter 为最长16字符的字符串；lens/camera 为最长64字符的字符串。不接收字符串数字，不做溢出截断或静默舍入，非法值返回400 invalid_request。PUT 保持原四字段契约，本版不扩展其 exif 输入。

发布事务同时写 `pwork(wstatus='待审核')`、可选 work_exif、`work_embedding(status='pending',vec=NULL)`；V004 将 vec 放宽为 NULL。实际向量编码、写 vec 和 ready/failed 状态归卡08；发布占位不能冒充向量已完成，公开检索仍只能包含展示作品。

公开列表、公共详情、同款和关注流只含 `wstatus='展示'`；mine 返回本人四种状态。对非展示作品的评论、点赞、收藏、关注一律404 not_found，包括读取、添加和取消，不能用作者或管理员身份绕过作品可见性。作品删除的从属数据清理必须按 V001 的真实约束处理：liketable.targetid 是多态列，没有 pid 外键，不能假定数据库会级联清掉帖子点赞。

latest 按 cwtime 降序；hot 按 likep+votecount 降序；相同值以 pid 升序稳定分页。**recommend 自 v1.3 起冻结为时间衰减热度**：`(COALESCE(likep,0)*2 + COALESCE(votecount,0)*5 + COALESCE(viewcount,0)/10.0) / SQRT(TIMESTAMPDIFF(HOUR, cwtime, NOW()) + 1)` 降序、`pid ASC` 兜底；这是全局热度衰减，新作品有曝光机会，**不是**按用户行为定制的个性化推荐。其结果同样只能包含展示作品。固定路径 `/pwork/mine`、`/pwork/following`、`/pwork/list` 不得被 `/{pid}` 当成ID放行规则吞掉。

**v1.3 变更汇总（B2/B3）**

- `Work` 对象新增 `pcid:ID?`（作品分类 id，可为 null），列在 `pcname` 之前；`/pwork/list`、`/pwork/{pid}`、`/pwork/mine`、`/like/mine` 等所有复用 Work 投影的接口一并返回。这是**纯增量**字段，不改变既有字段含义与顺序语义。
- `recommend` 排序算法正式冻结（见上），不再复用 latest 的时间序。
- 新增 `GET /like/mine`（见 §1.6 28b）。

**v1.4 变更汇总（B4/B5：关注流、收藏状态、他人主页、可见性）**

- **`GET /pwork/following`**（契约 #11 落地）：登录；返回「我关注的人」的「展示」作品，`ORDER BY p.cwtime DESC, p.pid ASC`；`total` 与列表同一过滤条件。
- **`Work` 增 `favoriteCount`**，**详情 `work` 增 `favorited`**（见 §1.1 对象表）。
- **`GET /user/{uid}` 权限放宽**：由「普通用户限本人」改为「任意登录用户可读他人公开资料」，并追加 `worksCount / followingCount / followersCount / followed / showFavorites / showLikes`。手机号对非本人不返回。
- **新增 `GET /user/{uid}/works`**：登录；只返回该用户「展示」作品，`cwtime DESC, pid ASC`。
- **新增 `GET /user/{uid}/favorites`**：登录；`user.vis_favorite=0` 且请求者不是本人 → **403 forbidden**；只返回展示作品，`favorite.ct DESC, fid ASC`。
- **新增 `GET /user/{uid}/likes`**：同上，用 `liketable`（`targettype='帖子'`）、`vis_like`、`likect DESC, lid ASC`。
- **新增 `PUT /user/privacy`**：登录；Body 必须含 `visFavorite:boolean` 与 `visLike:boolean`；只改当前登录用户，不接受 body 里的 uid；缺字段或类型非布尔 → 400。
- **数据层**：`user` 表新增 `vis_favorite TINYINT(1) NOT NULL DEFAULT 1`、`vis_like TINYINT(1) NOT NULL DEFAULT 1`；存量用户默认可见。作品列表不受可见性控制——主页作品 tab 天然只含「展示」作品。
- **已知现状（待定）**：`GET /user/{uid}` 目前对**所有人**（含本人与管理员）都返回 `pnum=null`，比 v1.3 的「掩码」更严格但也丢失了本人自助查看能力；如需恢复，由后续卡在 `userMapper.homeProfile` 补取 `pnum` 并复用 `maskPhoneFor`。

**v1.5 变更汇总（B6/B7/B8：移除粉丝、获赞总数、关系可见性）**

- **新增 `DELETE /follow/follower/{uid}`**：登录；删除「对方关注我」的关系（`follow.uid=对方 AND follow.tuid=我`），**不是取关**；关系不存在 → 404；移除自己 → 400；响应 `{ removed:true, followersCount:N }`，计数为删除后重查的真实值。
- **`GET /user/{uid}` 追加 `likedTotal:N`**：该用户所有**展示**作品 `pwork.likep` 之和（`SUM`，不是 `COUNT(liketable)`）。
- **`GET /user/{uid}` 追加 `showFollowing` / `showFollowers`**：`(u.vis_following=1 OR 请求者==目标)`，本人恒 true。
- **新增 `GET /user/{uid}/following`**：登录；返回**目标用户关注的人**（`follow.uid=目标`），`f.ct DESC, f.fid ASC`；`vis_following=0` 且请求者≠目标 → 403 forbidden；目标不存在 → 404；字段与 `/follow/following` 完全一致（`uid/nickname/avatar/bio`）。
- **新增 `GET /user/{uid}/followers`**：同上，`follow.tuid=目标`，受 `vis_followers` 控制。

## 二、共享契约

### 2.1 信封、分页、HTTP 与错误码

```json
{"code":"ok","msg":"操作成功","data":{"list":[],"total":0}}
```

顶层键集合必须恰为 `code:string,msg:string,data:any`；错误时data=null，删除成功data=null。不得带顶层total、success、status、message。非分页对象只返回接口表指定字段。分页total是过滤后的总记录数，不是当前页长度；空列表为`[]`，不是null。msg是安全中文提示，不承载分支判定，客户端只按HTTP及code判断。

成功通常HTTP200，发布#8固定201；二者code均为`ok`。错误的code是下表字符串，不能再用“HTTP与body.code数值相等”的旧说法。所有失败抛 `BizException(ErrorCode常量, 对应HTTP)`，由现有GlobalExceptionHandler输出；不能捕获后再返回HTTP200。`AjaxResult.success(String)`是提示文案重载，返回字符串data必须显式按Object或Map调用，不能把URL误当msg。

| ErrorCode常量 | body.code | HTTP | 状态/触发与安全msg |
|---|---|---|---|
| OK | ok | 200或201 | 已有；操作成功 |
| INVALID_REQUEST | invalid_request | 400 | 已有；请求参数不合法 |
| UNAUTHORIZED | unauthorized | 401 | 已有；请先登录；不新增unauthenticated别名 |
| FORBIDDEN | forbidden | 403 | 已有；无权访问该资源 |
| NOT_FOUND | not_found | 404 | 已有；资源不存在 |
| CONFLICT | conflict | 409 | 已有；数据冲突 |
| PAYLOAD_TOO_LARGE | payload_too_large | 413 | 已有；上传内容过大 |
| CONTENT_REJECTED | content_rejected | 422 | **卡02新增枚举项**；内容不合规 |
| INVALID_IMAGE | invalid_image | 422 | **卡02新增枚举项**；图片不合法 |
| INVALID_PROFILE | invalid_profile | 422 | **卡02新增枚举项**；个人资料不合法 |
| TOO_MANY_REQUESTS | too_many_requests | 429 | 已有；请求过于频繁；卡09接入5次/60秒/IP及Retry-After |

| SERVICE_UNAVAILABLE | service_unavailable | 503 | **卡02新增枚举项**；服务暂不可用 |

公共错误：缺必填字段、类型不符、格式错误、分页越界→400；受保护接口无/坏/过期凭证或主体不存在/禁用→401；已登录角色不足→403；路由不存在→404；错误HTTP方法→**405 + invalid_request**（保留基线例外）；上传框架拒绝过大请求→413；未捕获异常→500。表内不重复枚举每条接口的这些公共失败。

三个422常量必须由业务层明确选择，不能通过 `AjaxResult.error(422, msg)` 或 `ResponseStatusException(422)` 的“按状态取第一个枚举”方式选择。后续卡不复制新ErrorCode文件、不定义私有code字符串。唯一约束幂等冲突在对应业务事务内处理，不加全局 DuplicateKeyException→409 映射。未知SQL、文件IO故障归500；外部微信/文本安全服务不可用归503。

### 2.2 时间、ID、校验及列映射

新契约的 `T` 固定为带秒和偏移的 ISO 8601：`yyyy-MM-dd'T'HH:mm:ssXXX`，使用 `Asia/Shanghai`，示例 `2026-10-21T15:04:05+08:00`；不返回毫秒时间戳或仅日期。数据库DATETIME按同一时区解释。当前application.yml是`yyyy-MM-dd`，卡02–07不改全局Jackson配置，新增契约通过显式响应投影格式化；存量路由时间格式按U8维持原状，不安排既有断言迁移。

请求JSON数值不接受字符串数字代替；ID不接受数字。必填string不能为null；长度按Unicode字符数校验并保留原文，不用trim后的正文替代用户内容；“非空白”仅作拒绝判定。无明示枚举值、无明示长度上限的字段不得猜测另加产品限制。资料字段长度、作品字段长度以当前列宽为上限。

## 七、Java 代码风格（卡 01b 已全仓落地，后续卡必须遵守）

| 维度 | 规则 | 违规判定 |
|---|---|---|
| 类名 | 大驼峰 PascalCase（`UserController`、`PworkService`、`PworkServiceImpl`） | 首字母小写即违规 |
| 包名 | 全小写，无下划线 | — |
| 依赖注入 | 构造器注入 + `private final` 字段 | 出现 `@Autowired` 字段即违规 |
| 日志 | SLF4J：`private static final Logger log = LoggerFactory.getLogger(X.class);`，参数化 `log.info("uid={}", uid)` | `System.out`、`printStackTrace`、字符串拼接日志均违规 |
| 错误处理 | 业务失败 `throw new BizException(ErrorCode.X, "中文说明")`，由 `GlobalExceptionHandler` 出信封 | Controller 里 `AjaxResult.error(int, String)` 即违规 |
| 响应体 | 统一 `{code,msg,data}`；成功 `code="ok"`；分页在 `data.list/data.total`；不返回持久化实体 | 顶层出现 `total`、或返回实体带 `pwd/openid` 即违规 |
| 敏感字段 | `pwd` 用 `@JsonProperty(access=WRITE_ONLY)`；手机号非管理员脱敏 | 响应出现 `"pwd"` 即违规 |
| 格式 | 4 空格缩进、CRLF、UTF-8、禁通配 `import *` | — |
| 常量 | 魔法数字具名（积分上限 9999、长度 50/255 等） | 裸数字参与业务判断即违规 |
| 注释 | 类与公共方法中文 Javadoc；复杂分支写「为什么」 | 公共方法无注释即违规 |
| 测试 | 测试与实现不同工人；断言不许削弱、不许 `@Disabled`、不许 `skipTests` | — |

**一票否决**：同一 PR 内混用两套风格（例如新类用构造器注入、旧类仍 `@Autowired`）视为不通过。
