## 任务 A：分类新增（§8）

`POST /admin/category`，body `{pcname, cds?}`：
- pcname 必填、1–20 Unicode 字符、不得全空白、**不 trim**；重名字面完全一致 → 409 conflict「分类已存在」
- pcid 服务端生成 UUID(36 位去横线)，忽略客户端传入
- sort = 当前 MAX(sort)+10，在同一事务/同一 SQL 里算（`INSERT ... SELECT COALESCE(MAX(sort),0)+10 FROM pclist` 之类），避免并发撞号
- 成功 data 恰 `{pcid, pcname, sort}`
- 先查表结构（pclist）确认真实列名与列宽，不要猜；`SELECT *` 禁止

## 任务 B：封禁申诉（§7）

1) `POST /appeal`（匿名）body `{code, content}`：
- code2session 复用 AuthController 里与 `/auth/wxlogin` **完全相同**的 mock 规则（dev + `mock:` 前缀），**不要**自己发明第二套；建议抽出私有方法或复用现有 Bean，避免复制粘贴两份判断
- code 换不到 openid → 401 unauthorized
- content 1–200 Unicode 字且非全空白，否则 400 invalid_request
- openid 对应用户不存在 或 用户 status='正常' → **统一** 400 invalid_request，文案「账号不存在或无需申诉」（不泄露账号是否存在）
- 24h 内已有 status='待处理' 的申诉 → 409 conflict
- 同一 openid 每分钟 >1 次 → 429 too_many_requests（用 appeal 表按 ct 计数，不引入 Redis）
- 成功 `{aid, status:"待处理"}`

2) `GET /admin/appeal/list?status&page&size`：管理员；data 恰 `{list,total}`；每项恰 `aid,uid,nickname,avatar,content,status,ct,handler,hct,reason`；排序 `ct DESC, aid DESC`；status 只接受 待处理/已受理/已驳回，其它 400；size 1–50，page≥1。

3) `PUT /admin/appeal/{aid}/handle` body `{result:"接受"|"驳回", reason?}`：管理员
- 接受：**同一事务** `appeal.status='已受理'` + handler/hct，同时 `user.status='正常'`；**不恢复作品展示状态**
- 驳回：`status='已驳回'`，reason 必填 1–200，写 handler/hct
- aid 不存在 404；非「待处理」409 conflict
- 成功 data 恰 `{aid,status}`
